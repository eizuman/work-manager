# Текущее состояние и дальнейшие работы

## Статус документа

Документ перечисляет только ограничения, подтверждённые текущим кодом и составом репозитория. Порядок ниже — приоритет устранения рисков, рекомендованный по результатам аудита; утверждённые сроки, исполнители и целевая будущая архитектура неизвестны.

Точная модель данных находится в [DATA_MODEL.md](DATA_MODEL.md), устройство приложения — в [ARCHITECTURE.md](ARCHITECTURE.md), запуск и проверки — в [DEVELOPMENT.md](DEVELOPMENT.md).

## Реализовано в текущем коде

- OAuth token flow через Google Identity Services и проверка одного email.
- Хранение access token в `localStorage`, silent re-auth и logout.
- Отдельный spreadsheet для каждого объекта и общий `_registry`.
- Календарь планов, фактических работ, заметок и checklist.
- Ставка объекта и ставка отдельной записи работы.
- Автоматическое создание finance entry для записи работы с часами.
- Ручные операции finance и фильтры периода.
- Задачи, теги, исполнители, ручной порядок и планирование в календарь.
- Закупки с необязательной ссылкой на задачу.
- Статистика рабочего времени и Canvas-графики.
- Ручной и автоматический backup, restore и JSON export.
- Mobile и desktop layouts с desktop breakpoint 768 px.

Наличие реализации подтверждено статически. Runtime-работа с реальным OAuth-сеансом, внешними ACL и production spreadsheets в рамках аудита не проверялась.

## Приоритет 1: восстановимость и целостность данных

Подтверждённые ограничения:

- Backup читает семь объектных листов, restore заменяет пять и отдельно `hourly_rate`; `workers` и остальные settings не восстанавливаются.
- `last_auto_backup` хранится одним ключом browser profile, а не отдельно для каждого объекта.
- Metadata хранит не более десяти backup IDs, но код не удаляет более старые backup spreadsheets.
- Связь `work_log` и auto-generated finance entry основана на дате в `finance.description`, отдельного source ID нет.
- После некоторых удалений сохранённые `finance.balance` не пересчитываются.
- Удаление task, tag или worker не очищает ссылки из других сущностей.
- Многошаговые операции выполняются последовательными запросами и могут завершиться частично.

Перед дальнейшим расширением модели требуется определить и проверить ожидаемое поведение этих существующих операций. Конкретная новая схема или механизм миграции пока не утверждены.

## Приоритет 2: проверка и совместимость схемы

Подтверждённые ограничения:

- Версия схемы в данных отсутствует.
- Для подключаемого существующего Sheet ID нет полного schema preflight.
- Автоматический ensure есть для `_registry`, `workers` и `settings`, но отсутствует для `work_log`, `finance`, `tasks`, `tags` и `purchases`.
- Reader поддерживает таблицы с заголовком `id` и таблицы без заголовка.
- `work_log.date` используется как уникальный логический ключ, но Google Sheets не запрещает дубли.
- Checklist и task links хранятся в двух позиционно связанных строках с разделителем `|`.
- Append определяет следующую строку по заполненности колонки A.

До изменения колонок или сериализации необходимо сохранить чтение существующих строк. Утверждённой versioned migration system сейчас нет.

## Приоритет 3: безопасность и внешняя конфигурация

Подтверждённые ограничения:

- Access token хранится в `localStorage`.
- Email allow-list выполняется только клиентским JavaScript.
- Content Security Policy в HTML отсутствует.
- HTML формируется строками в нескольких модулях; escaping реализован несколькими разными функциями.
- Фактические Google Cloud origins, OAuth consent settings, Sheets ACL и активная GitHub Pages configuration репозиторием не подтверждаются.

Изменения OAuth scopes, хранения токена или hosting требуют отдельной проверки внешней конфигурации. Её текущее состояние неизвестно.

## Приоритет 4: корректность UI и аналитики

Подтверждённые ограничения:

- Finance statistics переводит сумму в часы через текущую ставку, хотя work logs хранят ставки отдельных записей.
- Фильтр статистических карточек не меняет периоды недельного и дневного графиков.
- Код смешивает UTC-даты через `toISOString()` и локальные компоненты `Date`.
- `TasksModule` объявлен top-level `const`, но `app.js` проверяет `window.TasksModule`; эти проверки не вызывают `reloadWorkers()` в модели classic scripts.
- Custom dialogs и bottom sheets не реализуют полный keyboard focus workflow.

## Приоритет 5: поддерживаемость и проверки

Подтверждённое состояние:

- `app.js`, `calendar.js`, `tasks.js` и `styles.css` содержат значительную часть логики и разметки проекта.
- State, HTML generation, event binding и domain operations объединены внутри UI-модулей.
- SVG и inline styles повторяются.
- В репозитории нет test runner, CI workflow, linter, formatter, HTML/CSS validator и Markdown link checker.
- Доступна только синтаксическая проверка JavaScript через `node --check` и ручные проверки, перечисленные в [DEVELOPMENT.md](DEVELOPMENT.md#проверки-перед-сдачей-изменения).
- `CONFIG.SPREADSHEET_ID`, `CONFIG.HOURLY_RATE` и `isDesktop` объявлены, но текущими вызовами не используются.

## Очерёдность перед функциональным расширением

1. Зафиксировать проверяемое поведение backup/restore и финансовой синхронизации на отдельном тестовом объекте.
2. Определить фактические правила удаления связанных сущностей.
3. Добавить проверку текущей схемы подключаемого spreadsheet без изменения данных.
4. Исправить подтверждённые расхождения UI и расчётов.
5. Добавить воспроизводимые автоматические проверки существующего поведения.

Эта последовательность не задаёт будущую архитектуру и не меняет текущую модель Google Sheets.
